## 三、Phase 1 — C 端后端收尾

> **目标:** 把下单→支付→物流闭环走通，后端链路完整可测

### 1.1 支付回调关联订单状态更新

**当前状态:** `PayServiceImpl.handleAlipayNotify` 只更新了 `trade_pay` 表，未联动 `trade_order`

**要做什么:**
1. 支付宝回调成功后，同步更新 `trade_order.order_status`：0(待支付) → 1(待发货)
2. 更新 `trade_order.pay_time`
3. 支付成功后扣减真实库存：`stock -= quantity`，`locked_stock -= quantity`
4. 微信回调同样逻辑

**涉及文件:**
- `src/main/java/com/mall/trade/service/impl/PayServiceImpl.java`

**验证:** 模拟回调请求 → 确认 `trade_order.order_status` 从 0 变为 1，库存正确扣减

---

### 1.2 Redis 库存预扣（Lua 脚本）

**当前状态:** 下单直接操作 DB 的 `pm_sku_stock`，存在高并发超卖风险

**要做什么:**
1. 编写 Lua 脚本：`if redis.call('get', KEYS[1]) >= ARGV[1] then redis.call('decrby', KEYS[1], ARGV[1]) return 1 else return 0 end`
2. 改造 `createOrder`：先 Redis Lua 预扣，成功后再走 DB 锁库存
3. Redis 预扣失败 → 直接抛 "库存不足"
4. 商品上架/库存变更时同步 Redis 库存缓存

**涉及文件:**
- `src/main/java/com/mall/trade/service/impl/TradeOrderServiceImpl.java`（createOrder 加 Redis 预扣）
- 新建 `src/main/java/com/mall/common/config/RedisStockScript.java`（Lua 脚本加载）

**验证:** JMeter 并发 100 线程下单 → 库存不超卖

---

### 1.3 订单超时取消定时任务

**当前状态:** 无自动取消机制，未支付订单永久占用库存

**要做什么:**
1. 新建 `OrderTimeoutJob`，`@Scheduled(cron = "0 */5 * * * ?")` 每 5 分钟扫描
2. 查询条件：`order_status = 0 AND create_time < now() - 30min`
3. 批量取消 + 释放锁定库存
4. 可选：发送 MQ 消息触发库存释放（解耦）

**涉及文件:**
- 新建 `src/main/java/com/mall/trade/job/OrderTimeoutJob.java`

**验证:** 创建订单不支付 → 30 分钟后自动取消，库存恢复

---

### 1.4 取消订单释放库存

**当前状态:** `cancelOrder` 只改状态，未释放 `lockedStock`

**要做什么:**
1. 在 `cancelOrder` 中遍历 `trade_order_item` 拿到 skuId + quantity
2. 逐个 `skuStockMapper` 释放：`lockedStock -= quantity`
3. 合并 1.3 超时取消和 1.4 手动取消的库存释放逻辑（共用方法）

**涉及文件:**
- `src/main/java/com/mall/trade/service/impl/TradeOrderServiceImpl.java`

**验证:** 取消订单 → 确认 `pm_sku_stock.locked_stock` 已恢复

### 3.2 Python AI 微服务核心代码

**当前状态:** `mall-ai-service/` 目录结构就绪但内容为空

**要做什么:**
1. `app/main.py` — FastAPI 启动入口，注册路由
2. `app/config.py` — 环境变量配置（LLM API Key、LangFuse Key、ES 地址）
3. `app/agent/agent.py` — LangGraph StateGraph 构建：意图识别 → 条件路由 → 工具调用 → 回复生成
4. `app/agent/tools.py` — Function Calling 工具定义（query_order, query_product, check_return, track_logistics 等）
5. `app/agent/prompts.py` — System prompt + 意图识别 prompt + 工具调用 prompt
6. `app/rag/retriever.py` — ES dense_vector + BM25 混合检索
7. `app/rag/embedding.py` — Embedding 接口封装（OpenAI / 本地模型）
8. `app/api/chat.py` — SSE 聊天端点
9. `app/api/knowledge.py` — 知识库 CRUD（向量化 + 写入 ES）
10. `app/api/eval.py` — 评测接口（运行测试集 → 返回评分）
11. `app/models/schemas.py` — Pydantic 请求/响应模型
12. `app/utils/llm.py` — LLM 客户端封装
13. `app/utils/tracing.py` — LangFuse trace 集成

**验证:**
```bash
cd mall-ai-service
uvicorn app.main:app --reload --port 8000
curl -X POST http://localhost:8000/api/chat -d '{"message":"帮我查订单T20240101001"}'
```
→ 返回 SSE 流式回复

### 3.3 SSE 全链路调通

**链路:**
```
Vue EventSource → Spring Boot SseEmitter → Python StreamingResponse
```

**要做什么:**
1. Spring Boot `AiChatController`：接收请求 → `SseEmitter` → HTTP 转发 Python → 逐行 emit
2. Python `chat.py`：`StreamingResponse` → token 级别流式输出
3. Vue 聊天气泡：`EventSource` 接收 → 增量追加 + 打字机光标
4. 错误处理：Python 服务不可用时降级提示

**涉及文件:**
- `src/main/java/com/mall/ai/controller/AiChatController.java`
- `mall-ai-service/app/api/chat.py`
- `mall-web/src/views/ai/ChatView.vue`

---

### 3.4 评测体系

**要做什么:**
1. 编写 50 条测试集（Excel/JSON）：用户问题 + 期望回答 + 分类标签
2. 实现批量运行：遍历测试集 → 调用 Agent → 收集回答
3. 实现 LLM-as-Judge：另一个 LLM 对比期望 vs 实际，输出 1-5 分
4. LangFuse 集成：每次 Agent 调用自动打 Trace
5. 前端评测页：上传测试集 → 一键运行 → 查看评分报告
