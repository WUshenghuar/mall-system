## 1. 实际架构

当前仓库不是早期文档规划的多 Maven 模块或独立微服务，而是：

```text
根目录单 Maven 模块（Java 23 / Spring Boot 3.2.5）
└── com.mall
    ├── product / order / trade / member
    ├── marketing / finance / search / security / system
    └── web（统一 Spring Boot 入口和 Controller）

mall-web/          Vue 3 + Ant Design Vue，B 端运营控制台
mall-storefront/   Vue 3 + Vant，C 端交易 H5
mall-ai-service/   Python 包骨架，AI 尚未实现
```

基础设施由 Docker Compose 提供：MySQL `3306`、Redis 宿主机 `16379`（容器 `6379`）、RabbitMQ `5672/15672`、Elasticsearch `9200`、MinIO `9000/9001`。

## 2. 当前已实现

- B 端：商品、分类、品牌、SKU、基础库存、订单、退款、会员、营销、财务、税率、系统用户/角色和基础看板。
- C 端后端：会员手机号密码认证、匿名商品目录、购物车、地址、收藏/足迹、结算复核、订单、库存预占/释放、模拟支付、物流和确认收货。
- C 端前台：`mall-storefront` 已提供商品、账户、地址、购物车、结算、订单和基础物流/收藏/足迹入口。
- 基础设施：Flyway、Redis Lua 多 SKU 预占、RabbitMQ 事务后交易事件、Docker Compose、UTF-8 开发种子导入脚本。

## 4. 启动与数据约定

1. 复制 `.env.example` 为 `.env`，填写本地凭据。
2. 执行 `docker compose up -d`。
3. 在仓库根目录直接执行 `mvn spring-boot:run`；Spring 会自动导入根目录 `.env`。
4. 开发种子数据使用 `powershell -ExecutionPolicy Bypass -File scripts/import_dev_seed.ps1 -Reset`，脚本强制以 `utf8mb4` 导入，禁止使用 PowerShell 文本管道直接喂给 `mysql`。
