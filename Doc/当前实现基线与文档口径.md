## 1. 实际架构

当前仓库不是早期文档规划的多 Maven 模块或独立微服务，而是：

```text
根目录单 Maven 模块（Java 23 / Spring Boot 3.2.5）
└── com.mall
    ├── product / order / trade / member
    ├── marketing / finance / search / security / system
    └── web（统一 Spring Boot 入口和 Controller）

mall-web/          Vue 3 + Ant Design Vue，B 端运营控制台
mall-storefront/   Vue 3 + Vant，C 端响应式交易前台（移动优先 + 桌面自适应 ≥1025px）
mall-ai-service/   Python 包骨架，AI 尚未实现
```

基础设施由 Docker Compose 提供：MySQL `3306`、Redis 宿主机 `16379`（容器 `6379`）、RabbitMQ 宿主机 `18110/18111`（容器 `5672/15672`）、Elasticsearch `9200`、MinIO `9000/9001`。

## 2. 当前已实现

- B 端：商品、分类、品牌、SKU、基础库存、订单、会员、营销、财务、税率、系统用户/角色和基础看板；交易退款页面已接入 C 端退款申请的待审、通过、驳回和确认退款流程，并显示处理备注。
- C 端后端：会员手机号密码认证、匿名商品目录、购物车、地址、收藏/足迹、结算复核、订单、库存预占/释放、物流和确认收货；结算会生成 15 分钟、一次性 Redis 快照 token，下单由服务端快照恢复商品与地址；支付宝回调具备 RSA2 签名、金额、订单归属与幂等校验。
- C 端前台：`mall-storefront` 已提供账户、地址编辑、购物车、结算、订单详情、物流详情、待支付取消、待收货确认、收藏/足迹独立页及仅退款申请/进度页；未登录访问交易页面会引导到会员登录。前台为移动优先的响应式布局：≤680px 保持移动单列与底部导航，≥1025px 自动切换桌面布局（顶栏横向导航、商品多列网格、内容限宽居中）。
- 退款闭环：C 端仅允许会员为自己的待发货交易订单申请仅退款；同订单处理中的申请不可重复创建。B 端可审核通过、驳回或确认退款；驳回会恢复待发货，确认退款将订单置为已退款。
- 基础设施：Flyway（含 `V5__add_trade_refund.sql`）、Redis Lua 多 SKU 预占、RabbitMQ 事务后交易事件、Docker Compose、UTF-8 开发种子导入脚本。

### 本轮验证口径

- 已通过：支付回调、结算快照、交易退款、购物车和订单归属等针对性单元测试；B/C 两端生产构建。
- 已执行：C 端 320/375/390/430px 移动视口模拟数据验收，无横向溢出，关键按钮高度不低于 44px；桌面自适应（1440px 视口）同样通过无后端 mock 验收，商品多列网格与顶栏导航渲染正常。

## 4. 启动与数据约定

1. 复制 `.env.example` 为 `.env`，填写本地凭据。
2. 执行 `docker compose up -d`。
3. 在仓库根目录直接执行 `mvn spring-boot:run`；Spring 会自动导入根目录 `.env`。
4. 开发种子数据使用 `powershell -ExecutionPolicy Bypass -File scripts/import_dev_seed.ps1 -Reset`，脚本强制以 `utf8mb4` 导入，禁止使用 PowerShell 文本管道直接喂给 `mysql`。
